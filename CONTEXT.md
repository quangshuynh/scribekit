## Current implementation

- Domain value types in `ScribeKit/Models/`: `MeetingState` (lifecycle with
  explicit transition rules), `AudioRetentionMode`, `CaptureSource`,
  `MeetingSession`.
- `ScribeKit/Features/MeetingSetup/MeetingSetupView.swift`: title field,
  retention picker, folder chooser, disabled Start Meeting, unavailable source
  area.
- `ScribeKitTests/`: Swift Testing suites for the four model types.
- `.github/workflows/ci.yml`: builds and runs unit tests on `macos-26`.

No capture, transcription, persistence, recovery or background behaviour exists.

## Established decisions

- Deployment target stays macOS 26.5, as generated by the project template; CI
  therefore needs an Xcode 26 runner image.
- Swift Testing (not XCTest) for unit tests. The template UI test target still
  exists but is skipped in the shared scheme and not run by CI.
- Session lifecycle is one enum, with transitions validated in
  `MeetingState.canTransition(to:)` and applied by
  `MeetingSession.transition(to:)`, which throws `MeetingStateError`.
- No `failed` state: recoverable interruption is expressed by `recovering`, and
  ending always passes through `stopping` to `completed`.
- `MeetingSession` holds metadata only; transcript and audio storage will live
  in separate types so raw transcripts stay decoupled from bookkeeping.
- CI signs ad-hoc (`CODE_SIGN_IDENTITY=-`) so the sandboxed host app launches
  for unit tests without team credentials.
- No third-party dependencies.

## Known limitations

- Save location is not persisted; no security-scoped bookmark yet.
- `CaptureSource` has no discovery mechanism — nothing populates it.
- The UI has no view model; state lives in the view, which is adequate while
  there is no session coordinator.
